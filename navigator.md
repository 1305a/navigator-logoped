# Описание работы программы.

Нужно сделать макет программы.

Цель макета: визуализировать сценарии работы логопеда с пациентом для обсуждения с врачами. Макет должен выглядеть и «щёлкаться» как настоящий сервис, но не являться им

Что делаем:
•	Кликабельный прототип (frontend-only): экраны, переходы между ними, статичные состояния
•	Имитация всех кнопок, полей, чекбоксов, диалогов — визуально рабочие, с переходом на следующий экран/шаг
•	Захардкоженные (заранее заданные) демонстрационные данные: Несколько примеров пациентов, готовые заполненные карточки, готовые заключения
•	Наглядная имитация «диалога с системой» — переход по заранее прописанному сценарию (без реального анализа данных)

Чего НЕ делаем на этом этапе:
•	Никакого backend — нет сервера с бизнес-логикой
•	Никакой базы данных — нет сохранения данных между сессиями
•	Никакой авторизации / реальных пользователей и ролей — переключение ролей может быть простым выбором на стартовом экране
•	Для авторизации используется заранее созданный список пользователей с ролями. На каждую роль по одному пользователю.
•	Никаких реальных алгоритмов и рекомендаций — рекомендации системы в «диалоге» показываются как заранее заданный текст
•	Никакой валидации форм, обработки ошибок, безопасности — это не нужно для демонстрации

Все данные, которые пользователь «вводит» в формы, можно either визуально принимать (без сохранения), либо использовать заранее подготовленный набор демо-данных, который подставляется вместо реального ввода. Выбор конкретного технического подхода — на усмотрение разработчика, критерий один: экран должен выглядеть и ощущаться как рабочий продукт.

Платформа «Навигатор логопеда» — цифровая среда работы логопеда, специализированный аналог электронной медицинской карты для логопедической практики.

Технические ориентиры для макета
•	Frontend-приложение без сервера — все данные хранятся в памяти приложения (переменные/состояние), пропадают при обновлении страницы — это нормально для макета
•	Адаптивность: приоритет — десктоп/планшет (демонстрация с ноутбука/экрана), мобильная версия не обязательна
•	Внешний вид: чистый, клинический, спокойный стиль — целевая аудитория показа — врачи, а не конечные пациенты
•	Важна не глубина проработки каждого экрана, а цельность сквозного сценария — переход от одного экрана к другому без «тупиков»
•	Там, где реальная логика не нужна (расчёты, рекомендации, генерация текста) — использовать заранее подготовленный статичный результат


## Авторизация

- Стартовый экран начинается с авторизации в котором выбор пользователей и пароль.
- пользователь обозначен как пользователь, а в скобках написано его роль 
- изначально заведены демо пользователя с ролями на каждую роль по одному пользователю.
- Пароль не задан, вход осуществляется при любом значении пароля.

## Роли.

- Роли заданы изначально
- Список ролей: Медсестра, Администратор, Логопед, Пациент
- Для каждой роли доступен свой список меню и свои экраны

## Разделы и пункты меню для логопеда:

- Рабочий стол (Открывается по умолчанию). Содержит виджеты:
    * назначение пациентов данному логопеду (список назначенных пациентов данному врачу)
    * График приема на ближайшие три дня.
- График приема. График приема пациентов логопедом.
- Банк упражнений. Содержит две вкладки, одна Онлайн, другая Оффлайн. Во вкладке Онлайн - список тренажеров (Онлайн-тестирование для пациентов). В вкладке Оффлайн - фраза раздел будет добавлен позже.
- Мои пациенты - список пациентов. Столбцы «Номер», «ФИО», «Тариф», «Заметки», «Дата последней активности», «Средняя оценка», «Подробности по пациенту». Заполни тестовыми данными 7 пациентов. В графе «Подробности по пациенту» кнопка «Подробности». При нажатии на нее проваливаемся на страницу подробных данных по пациенту (Страница пациента).     
- Мой профиль - Фотография врача (сгенерируй если можешь), дата рождения, опыт, другие характеристики сам дополни.

### Страница пациента
4 раздела - Информация о пациенте, Речевая карта, Программа, Список упражнений. Разделы Программа и Список упражнений не доступны до тех пор пока не будет заполнена речевая карта и там нажата кнопка «Составить программу».
* Информация о пациенте. Информация, которую заполнила медсестра
* Речевая карта 
    Придумай тестовый опросник по тематикам:
    1.	Биологические
    •	Заболевание (медицинский диагноз), лежащий в основе РР
    •	Длительность заболевания (речевого расстройства)
    •	Высокая утомляемость (толерантность к психической нагрузке)
    2.	Психологические портрет 
    •	Когнитивный статус
    •	Мотивация, (факт-чекинг прошлой истории)
    •	Адекватные ожидания
    •	Сформированный запрос (влияние на жизненные потребности)
    3.	Социальные
    •	Поддержка ближайшего окружения
    •	Увлечения (справочник типичных интересов)
    Внизу кнопка «Составить программу».    
* Программа. Какая-то демо-программа по работе логопеда с пациентом составленная на основе заполнения речевой карты., также список упражнений, которые надо выполнить. При нажатии на упражнение переходим в список упражнений.
* Список упражнений. напротив каждого есть кнопка "начать занятие". При нажатии на нее открывается страница с этим упражнением. Пока размести на этой странице кнопку начать, а также кнопку закончить упражнение. При нажатии на кнопку закончить упражнение, формируется отчет по упражнению. Количество верных ответов, количество неверных ответов, а также время, за сколько оно было выполнено. У этого отчета есть кнопка закрыть.


## Разделы и пункты меню для пациента:

## Разделы и пункты меню для администратора:

- Общие - Форма: название учреждения, Типы финансирования (бюджет, ОМС, ДМС, платные услуги) (чекбоксы)
